# The top Command

`top` shows system information and running processes. It looks basic, but the data it collects is vast and informative.

```bash
top     # run it
q       # quit
```

---

## 1. Reading the top screen

### Line 1: uptime and load

```
top - 19:38:28 up 2 days, 20:47, 0 users, load average: 0.52, 0.58, 0.59
```

- `19:38:28`: current time
- `up 2 days, 20:47`: uptime (time since last system start)
- `0 users`: active users (similar to `who`)
- `load average`: average for the last 1, 5 and 15 minutes
- Same first line as the `w` command

**Remember:** load average = average number of processes running and waiting for CPU time. Judge it against the number of CPUs / cores / threads. A load of 10 is a massive overload on 1 core, but fine on 12 cores.

### Line 2: tasks

```
Tasks: 6 total, 1 running, 5 sleeping, 0 stopped, 0 zombie
```

| Field | Meaning |
|---|---|
| total | All processes (does not include everything, e.g. idle) |
| running | Using CPU right now |
| sleeping | Waiting for something (e.g. I/O operation) |
| stopped | Stopped processes (e.g. by `ctrl+z`) |
| zombie | Finished its job but still has an entry in the process table, waiting for `exit()` |

- Zombie can happen when the parent process misbehaves
- Sometimes it can be killed by killing the parent, often it won't work

### Line 3: CPU

```
%Cpu(s): 13.9 us, 9.5 sy, 0.0 ni, 76.3 id, 0.0 wa, 0.4 hi, 0.0 si, 0.0 st
```

| Field | Meaning |
|---|---|
| `us` user | All user processes combined (including our sessions) |
| `sy` system | Processes owned by the system (kernel) |
| `ni` nice | Processes with niceness above 0 (run when "system will have time for it") |
| `id` idle | System is doing nothing |
| `wa` iowait | Waiting for input/output (subset of idle). Can show issues in other hardware |
| `hi` hardware interrupts | Physical interrupts from hardware, handled by the CPU |
| `si` software interrupts | Generated by software, handled by the kernel |
| `st` steal time | Time "stolen" from the VM by the hypervisor. Important in virtualized environments |

**Remember:** `nice` changes process priority. Default is `0`, range is `19` (lowest) to `-20` (highest).

### Lines 4 and 5: memory

```
MiB Mem :  16217.5 total,   6184.9 free,   9808.7 used,    224.0 buff/cache
MiB Swap:  49152.0 total,  48436.2 free,    715.8 used.   6278.3 avail Mem
```

- Line 4: physical memory. Line 5: swap
- `buff/cache`: buffer memory (kernel) + page cache
- `avail Mem`: max memory a newly starting program can use

### Process list fields

| Field | Meaning |
|---|---|
| `PID` | Unique process ID |
| `USER` | Process owner |
| `PR` | Default priority, set by the kernel at start |
| `NI` | Nice value (if nice was applied) |
| `VIRT` | Total memory used by the process |
| `RES` | RAM used by the process |
| `SHR` | Memory shared with other processes |
| `S` | Process state |
| `%CPU` | Share of CPU used |
| `%MEM` | Share of memory used |
| `TIME+` | Total CPU time used |
| `COMMAND` | The command being executed |

## 2. Modify the default view

### CPU and memory display

- `1`: toggle unified CPU view (`Cpu(s)`) and per-core view (`Cpu0`, ...)
- `t`: change CPU visualisation
- `m`: change memory visualisation

### Sort the process list

Default is by CPU usage.

- `M`: by memory
- `N`: by PID
- `T`: by running time
- `P`: by CPU (back to default)

### Tasks, threads, paths, trees

- `H`: switch between tasks and threads
- `c`: switch between command name and full path
- `v` / `V`: show process tree (parent / child relations)

### Filter and search

- `n`: limit number of shown processes (`0` = all)
- `u`: show processes of one user
- `o`: search, case-insensitive
- `O`: search, case-sensitive
- `enter` confirms, `ESC` rejects (prompt appears above the process list)

### Refresh and kill

- `s`: change refresh rate (default 3 seconds)
- `k`: kill a process (then enter the PID)

### Save settings

- `W`: write current settings to `toprc` in the home directory (sometimes `.toprc`)

```bash
cat .config/procps/toprc    # view saved settings
man top                     # manual, much more to explore
```

---

## 3. Start with non-default settings

```bash
top -o %MEM     # sort by memory
top -c          # show full paths
top -u root     # show processes owned by root
```

| Key | Action |
|---|---|
| `q` | Quit |
| `1` | Per-core CPU view |
| `t` / `m` | CPU / memory visualisation |
| `M` `N` `T` `P` | Sort by memory / PID / time / CPU |
| `H` | Tasks / threads |
| `c` | Command name / full path |
| `v` `V` | Process tree |
| `n` | Limit number of processes |
| `u` | Filter by user |
| `o` `O` | Search (case-insensitive / case-sensitive) |

| `k` | Kill a process |
| `W` | Save settings |
